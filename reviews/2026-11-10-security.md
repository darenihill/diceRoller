# What could leak or be abused (STRIDE), fourth pass (2026-11-10)

The first three passes (30 October, 7 and 8 November) fixed bad backups
crashing History, Games and Usage stats, share links reaching Google
Analytics, outside links reaching back into the tab, and links opened in an
open tab. This pass re-checks every door with crafted input in the browser
(production build, 390×844), and looks hardest at what changed since: the
Google tag loader added on 9 November (`src/utils/analytics.ts`, `index.html`).
Screenshots are in `dice-roller/2026-11-10/review48/`.

**Short answer:** one real hole, fixed: a share link could still carry a
popular game's name on other dice by hiding a character in it. Nothing runs
from a link, a backup or storage. One small service-worker issue is an idea.

## Where data crosses in and out

| Way in or out | Guard | Tried in the browser |
|---|---|---|
| Share link `#share=` | 1 MB unpacked cap, `sanitizeDiceList` (50 dice, 1–1000 faces, 100 faces of 60 characters, hex colors only, names 40 characters), a popular game's name only on its own dice | Faces `<img onerror>`, `"><svg onload>`, `javascript:`; a die named `<script>`; color `red;background:url(…)`; a 500-character name; broken data. Nothing ran, the color fell back to white, the name was cut to 40, broken data left the dice as they were (`sec-xss.png`, `sec-longname.png`) |
| Link name check | Popular-game names | **"Cat​an" (a zero-width space) showed "Catan" on two dice that only roll 6, fixed** (`sec-catanZW.png`, `sec-catanZW-after.png`) |
| Backup file | Every dice list sanitized; pictures must be small `data:image/png|jpeg|webp` | Games named `__proto__`, `constructor` and `<img onerror>`, a 9999-face die, junk History rows, theme `theme-dark evil`, an SVG picture and a `javascript:` picture. Nothing ran; the theme stayed dark; the SVG and `javascript:` pictures were dropped; History showed "No rolls yet" (`sec-backup-import.png`) |
| Local storage | Every key read through a check | NaN size, a huge modifier, a bad Advantage word, saved rolls as an object, a default set with `null` and `-5` faces, a 10,000-character target list. The app opened with sensible dice, no blank screen (`sec-poisoned-storage.png`) |
| Pictures as data URLs | Re-drawn to 128 px on the way in; only raster `data:` URLs kept | SVG (which can carry script) refused, as above |
| Google tag loader (new 9 Nov) | Not fetched while metrics are off; `ga-disable` set; `page_location` without the `#` part | Watched every Google request (fresh link, link in an open tab, dialog then Back, metrics off mid-visit). No hit carried a die name, face or the link; after Off no hit was sent in the next 11 seconds of rolling |
| Third-party scripts | Google tag only (plus Google Fonts CSS); Donate and Feedback open with no referrer | No other outside script in the build |
| Landing pages | Their own HTML, same tag loader | All four skip Google's script with metrics off |
| Service worker cache | Same-site files and Google Fonts only; never dice | Read from the code (the browser won't run a worker on a test address) |

## STRIDE walk

| Kind | Finding | Verdict |
|---|---|---|
| Spoofing | A link named "Catan" with a hidden zero-width space or joiner, full-width letters ("Ｃａｔａｎ") or a space ("Cat an") passed the name check, so loaded dice (two d6 that only roll 6) showed as "Catan" | **Fixed:** the check compares names as they read on screen: look-alike widths folded, hidden characters and spaces dropped, any case. Catan's own dice keep the name |
| Spoofing | A link name with a right-to-left mark ("‮natac") showed as "catan" | **Fixed:** direction marks are taken out of link names |
| Spoofing | Letters from another alphabet that look Latin (Cyrillic "С" in "Сatan") still pass | Accepted: telling look-alike alphabets apart needs a confusables table; the prize is a fake label on a free dice app |
| Tampering | A crafted backup or storage value | Checked above. Nothing to fix |
| Tampering | A backup's Usage stats can put any name in "Most played games" (`<b>x</b>`, shown as text) | Accepted: only the person's own file, shown as plain text |
| Repudiation | No accounts, nothing shared between people | Nothing to fix |
| Information leak | The service worker saves a copy of the page for every address with a query, keyed on the full address, so `?fbclid=…` or `?gclid=…` ad-click ids stay in the phone's cache, one copy each, until the next version | Idea: key the page copy on the path alone. Small, but it changes the offline code on a public site and couldn't be walked here |
| Information leak | Google Analytics on by default with no first-visit notice | Already an idea; not repeated |
| Denial of service | A crafted link unpacks before the 1 MB cap | Accepted on 8 November; unchanged |
| Elevated access | No `eval`, no server; the only raw HTML is our own landing text | Nothing to fix |

## Checked and fine

- `npm audit --omit=dev`: 0 issues in what ships.
- No secrets in the code; the analytics ID is public by design.
- `VITE_ANALYTICS_ENDPOINT` is not set, so events go nowhere but Google.

## Fixes built

- A share link's name is checked as it reads on screen, so hidden
  characters, wide letters or a space can't put a popular game's name on
  other dice, and direction marks are taken out of link names
  (`src/test/review20261110.test.tsx`).

## Not done, still worth a look

- A Content-Security-Policy, carried from earlier passes; already an idea.
- The service worker's per-query page copies (above).
