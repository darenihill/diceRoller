# Polish: forms and input (2026-10-22)

Lens: do inputs use the right keyboard, sensible defaults and autofill, and
validate gently and in place?

Screens checked at phone width (390 x 844, touch) in Chromium: Dice Settings,
Save Game, Customize (Target Highlight) and the Share Link fallback. Compared
one flow at a time with widely loved apps: the iOS Clock timer and Google
Calendar's number fields (tap selects the value, a number pad, Done closes the
keyboard), Google Keep's title field (no autofill suggestions on a free-text
name) and Material 3's text field spec (every field has a label tied to it;
errors show as supporting text under the field).

## Found

| Screen | Field | Problem | Standard |
|---|---|---|---|
| Dice Settings | Standard Faces box | It refused an empty value, so on a phone deleting the 6 and typing 12 gave **612** faces (reproduced: `6 -> backspace -> 6 -> type 12 -> 612`). Full keyboard, not a number pad. | Number pad; tap selects; can be cleared and retyped |
| Dice Settings | Name, Standard Faces | Visible labels not tied to the inputs, so screen readers read them as unnamed fields | M3: label tied to its field |
| Dice Settings | Add custom text, its + button | No accessible name on either | Named controls (DESIGN.md §6) |
| Dice Settings | Counts-as boxes | Enter did nothing | Done key closes the keyboard |
| Save Game | Name | Label not tied to the field; browser autofill could offer unrelated names; Enter key showed a generic return | Label, autofill off, Done key (Enter already saves) |
| Customize | Target Highlight | Browser autofill could offer unrelated entries; Enter did nothing | Autofill off, Done key |
| Share Link | Link box | Label not tied to the box | Label tied to its field |

## Done (fixes)

- Standard Faces box keeps what you type while you type it, selects its value
  on tap, uses the number pad, and goes back to the die's count if you leave
  it empty. After: `6 -> clear -> type 12 -> 12`; clear and leave -> back to 6;
  the - and + buttons still step from the shown count.
- Labels tied to their fields in Dice Settings, Save Game and Share Link;
  the custom-text field and its + button now have names ("Custom face text",
  "Add face").
- Autofill off on the die name, save name, custom text and Target Highlight.
- Done key (enterKeyHint) on the die name, faces, counts-as, save name and
  Target Highlight; pressing it closes the keyboard (Save Game still saves).

Nothing added, removed or moved; no new steps.

## Design tweaks built

None.

## Left as is

- Target Highlight stays a text keyboard: it needs commas, and phone number
  pads don't reliably have one.
- Counts-as boxes keep their number pad; iPhone's pad has no minus sign, so a
  negative count needs the hardware keyboard. Rare; noted only.
- Typing a new count in Standard Faces still clears a die's custom faces at
  once, as the - and + buttons always have. Losing them with no way back
  belongs with the "Undo after removing" idea already on the Focus tab.

## Suggested next goal (Focus tab)

- **Check target numbers as you type**: a gentle note under Target
  Highlight when part of it isn't a number ("'eleven' isn't a number, so only
  7 counts"). A new message, so it is a suggestion, not built.
