# What could leak or be abused (STRIDE), second pass (2026-11-07)

The first pass (30 October) fixed bad backups crashing History and Games,
share links reaching Google Analytics, and outside links reaching back into
the tab. This pass re-walks the same doors after a week of new features (new
version bar, Sort dice, color picker, share sheet, table view).

## Where data crosses in and out, now

| Way in or out | New since 30 Oct | Guard |
|---|---|---|
| Share link `#share=` | Share sheet first, copy box as backup | Unchanged: `sanitizeDiceList` limits; `#` part never reaches analytics (`gtag config page_location`). Opening a link in the walk worked |
| Backup file (Import) | Saved typed rolls, buzz, and now Table view, Bright Rings, Sort dice | Dice, history, games, theme, typed rolls checked. **Usage stats were not** (fixed below) |
| New-version check | Fetches our own `index.html` every 30 min while open | Same site, no-store, only reads the main script's name; nothing is run from it |
| Google Analytics | Unchanged | Kill switch honoured at load and when the switch flips. **The switch didn't say where data goes** (fixed below) |
| Landing about text | Unchanged | Our own HTML, built at publish time; the only `dangerouslySetInnerHTML` |

## STRIDE walk

| Kind | Finding | Verdict |
|---|---|---|
| Spoofing | A share link can carry any set name, including a built-in one like "Catan", for different dice | Already on the Desk ("Share links can't use a built-in game's name for other dice") |
| Tampering | A backup whose usage stats hold a blank or wrong-typed count blanked the whole app each time Usage Stats opened (walked: screen went empty, `Cannot convert undefined or null to object`) | **Fixed:** stats are checked on load; bad values fall back to defaults |
| Tampering | Saved-game names from a backup have no length limit | Accepted: shown as plain text; the worst is a long row on Games |
| Repudiation | Nothing shared between people | Nothing to fix |
| Information leak | The metrics switch said "anonymous usage stats & session telemetry" and never named Google Analytics, on by default | **Fixed (standard 15):** it now says what goes to Google Analytics and what never does |
| Information leak | Backups carry a random visitor id inside usage stats | Accepted: it never leaves the phone except in the file the person exports |
| Denial of service | Share and backup limits hold; the new-version check only runs while on screen | Accepted |
| Elevated access | No server, no roles, no `eval`; only our own HTML is injected | Nothing to fix |

- The service worker passes the version check to the network and still caches
  only our files and Google Fonts.
