# What Dice Roller keeps about you, where, and for how long (2026-11-09)

First privacy pass. Read from the code (`src/utils/savedValues.ts`,
`analytics.ts`, `faceImages.ts`, `backup.ts`, `index.html`, `public/sw.js`)
and checked in the running app, with Google Analytics live (walked at the
machine's network address, since it stays off on localhost). Screenshots are
in `dice-roller/2026-11-09/review42/`.

**Short answer:** nearly everything stays on the phone, in the browser's
local storage, until you delete it. What leaves is Google Analytics (on by
default) and whatever you put in a share link. Three things a careful user
would object to were real; all three are fixed in this pull request.

## What is kept, where, and for how long

| What | Where | Holds anything personal? | How long |
|---|---|---|---|
| Saved games, and the dice that were out last time | local storage `diceConfigs` | Game and die names, face words you typed | Until you delete the game |
| Default dice | `defaultDiceSet` | Same as above | Until you set new ones |
| History | `rollHistory` | Each roll's dice, names, colors, the game's name | Last 200 rolls, until Clear History |
| Pictures on faces | `diceFaceImages` | **Your photos**, shrunk to 128 px squares (re-drawn, so no camera or location data) | Until another picture is added after the face or die is gone (see "Still open") |
| Typed rolls saved as buttons | `savedRolls` | Their names | Until removed |
| Usage stats | `diceAnalyticsStats` | First and last day used, visit count, roll totals, which popular games you load, a random ID nothing reads | Until you clear the browser's data; no reset in the app |
| Settings (theme, sound, size, RPG mode, switches, Target hit, +2 and Advantage) | about 14 small keys | No | Until changed |
| Metrics switch | `telemetryEnabled` | No | Until changed |
| Back-button marker | the browser's history entry, `diceOverlay` | No | The visit |
| Service worker cache | `diceroller-v4` | No: only the app's own files and the Roboto font, never your dice | Until the next version |
| Backup file | your Downloads, `diceroller_backup.json` | Everything above, the random ID included; pictures only while a face still uses them | Wherever you keep it |

## What leaves the phone

| What | To whom | When | Guard |
|---|---|---|---|
| Page views, rolls (count, total, modifier), switch taps, popular game names, screen size, where you came from | Google Analytics | Every visit, while metrics are on (the default) | Never face words, pictures, your game names or the share link's `#` part. Checked live: after opening a link with "Smith family" in it, no hit carried it |
| Google's ID cookies `_ga` and `_ga_<id>` | Google, on each hit | Kept about 13 months (the walk's cookies ran to 14 Dec 2027) | **Now deleted** when metrics go off (fixed below) |
| A request for Google's tag script | Google's tag server | Every visit, **even with metrics off** until this pass | **Now skipped** while metrics are off (fixed below) |
| A request for the Roboto font | Google Fonts | Every visit, cached after | Not changed; idea below |
| Share link | Whoever you send it to | When you share | Carries die names, face words and the game's name, never pictures. The `#` part never reaches our server or Google |
| Feedback and Donate | Google Forms, Buy Me a Coffee | Only when tapped | Opened with no referrer |

## What a careful user would object to

| # | Objection | Found | Verdict |
|---|---|---|---|
| 1 | "I turned metrics off, but Google still hears from my phone every visit." | Each visit downloaded Google's tag script anyway, which tells Google the visit happened and from where (`s3-metrics-off-after.png`, walk log) | **Fixed**: with metrics off the script isn't fetched; switching on fetches it there and then |
| 2 | "I turned metrics off, but Google's ID is still on my phone." | `_ga` and `_ga_LF0JH7CVP6` stayed until December 2027 | **Fixed**: deleted when the switch goes off, and on each visit while it stays off (catches cookies from before this fix) |
| 3 | "I restored my backup and metrics came back on without asking." | Almost every backup says "on" (the default), and Import copied it over this phone's "off" (`p1-import-turns-metrics-on-before.png`) | **Fixed**: a backup can turn metrics off, never on (`p1-import-turns-metrics-on-after.png`) |
| 4 | "I removed my child's photo, but it's still on the phone." | The picture stays in storage after the die is removed and the page reloads (`s2-removed-die.png`) | Idea: changes what is saved, so it is a card (standard 15) |
| 5 | "How do I wipe everything?" | No one step: Clear History leaves Usage stats, games and pictures; the stats screen says to clear browser data (`s4-usage-stats.png`) | Idea |
| 6 | "You call it anonymous, but Google keeps an ID." | The switch is named "Anonymous page metrics" (DESIGN.md §7) while Google's cookie is a 13-month ID | Idea: a word-list change is Daren's |
| 7 | "Google is told I opened the site even with metrics off." (fonts) | Roboto comes from Google Fonts each first load | Idea: serve the font from our own site |
| 8 | GA is on with no first-visit notice | Already an idea from the 8 November security pass; not repeated | — |

## Fixes built

- With metrics off, no page fetches Google's tag script (home and the four
  search pages), and turning metrics on fetches it without a reload.
- Google's `_ga` cookies are deleted when metrics go off and on each visit
  while off.
- Import backup can't turn metrics back on.

All three in `src/test/review20261109.test.tsx`.

## Standards applied

- Privacy | Every page, with metrics off | Before: each visit fetched Google's tag script | After: nothing is fetched from Google's tag server (`src/test/review20261109.test.tsx`)
- Privacy | Customize, metrics switch | Before: Google's ID cookies stayed 13 months after turning off | After: they are deleted (`src/test/review20261109.test.tsx`)
- Privacy | Games, Import backup | Before: a backup turned metrics back on | After: a backup can only turn them off (`src/test/review20261109.test.tsx`)

## Still open

- Removed pictures linger (objection 4) and there is no "erase everything"
  (objection 5): both change saved data, so both are Desk ideas.
- The random visitor ID in Usage stats is never read or sent; it is harmless
  but could go in a later saved-data change.
