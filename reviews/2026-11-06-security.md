# Security review, second pass (2026-11-06)

Dice Roller is still a static site with no accounts, server or secrets. Every
fix from the first pass (2026-10-30) still holds. This pass found two new
problems, both coming in through a hand-made backup file, and one cheap way to
freeze the page with a share link. None of them can run code on the page.

## Where data crosses in and out

| Way in or out | Who controls it | Guard today | Verdict |
|---|---|---|---|
| Share link `#share=…&name=…` | Anyone who sends a link | `readShareLink`: lz-string, then `sanitizeDiceList` (50 dice, 1000 faces, 100 faces of 60 characters, hex colours only); the name is cut to 40 characters; React escapes all text | Escaping holds. **No size cap before `JSON.parse`** (fix 2) |
| Backup file (Import) | Anyone who hands someone a file | Dice, history, saved games, theme, typed rolls and pictures are all checked | **`usageStats` is stored as-is** (fix 1). `targetHighlight` has no length cap (fix 3) |
| Typed roll box | The person typing | `parseRollNotation`: anchored regexes with no backtracking, 50 dice, 2–1000 sides, ±999, box limited to 40 characters | Fine |
| Saved typed rolls (storage and backup) | Device or backup file | `sanitizeSavedRolls`: re-parsed, name 20 characters, 20 at most | Fine (`9999d6` was dropped in the test) |
| Face pictures | The person's photos, or a backup | `data:image/(png\|jpeg\|webp);base64` only, 60 KB each, 200 at most, ids `[a-z0-9]{1,16}` | Fine (an SVG data URL was dropped in the test) |
| Landing pages `data-start` and about text | Us, at build time | Attribute is escaped at build; `parseLandingStart` sanitises again; about HTML is our own markup | Fine |
| `#try-buzz` link | Anyone | Only turns on the phone's buzz and shows its switch | Fine. It isn't secret, and doesn't need to be |
| New-version check | Our own origin | Same-origin fetch of `index.html?version-check=…`; a regex reads the script name; only a yes/no comes out | Fine |
| Service worker | Our own origin | GET only; same origin and Google Fonts only; the version check skips the cache; only responses with status 200 are cached | Fine. Each different `?query` adds one more cached page on that device. Small, and stays local |
| Shake / motion | The browser | `requestPermission` only after a tap | Fine |
| Google Analytics | Sent while telemetry is on (on by default, with an off switch) | `page_location` has no `#` part; the hash is cleared with `replaceState` before gtag loads; events carry counts and built-in game names only; `session_start` sends the referrer and screen size | Fine. **A backup can quietly turn it back on** (fix 1) |
| Outside links (donate, ideas) | Outside sites | `noopener,noreferrer` | Fine (first-pass fix holds) |
| Deploy workflow | GitHub Actions on pushes to master | `contents: read`, `pages: write`, `id-token: write`, given to the whole job | Works. Could be tighter (see Needs Daren) |
| npm, shipped code | Package authors | `npm audit --omit=dev`: 0 issues | Fine. 17 dev-only issues (vitest/tinypool, vite, eslint, zod) are for the dependency lens |

## STRIDE walk

| Kind | Finding | Verdict |
|---|---|---|
| Spoofing | A share link can carry a built-in game's name with different dice. `&name=Catan` on two d6 that only roll 6 opens as "Loaded game: Catan" and is filed under Catan in History. It shows as plain text, and the faces can be seen in Dice settings. | Low. Accepted, optional fix below |
| Spoofing | Script-like names (`<img onerror>`, `<script>`) in the name, faces or die name show as text. A colour like `red;background:url(//evil)` falls back to white. | Tested: nothing ran. Fine |
| Tampering | **A backup's `usageStats` reaches storage unchecked** (backup.ts:82). `getLocalStats` spreads it over the defaults (analytics.ts:53). With `presetsLoadedCount: null`, every load of a built-in game throws in `trackEvent` (analytics.ts:148). `handleLoadSet` calls `trackEvent` before it closes the modal (App.tsx:463-475), so the Games screen stays stuck open over the dice after every preset load. This lasts until site data is cleared. | **Fix 1.** Reproduced in Chromium: `Cannot read properties of null (reading 'Catan')`, and the overlay blocks Roll |
| Tampering | First-pass guards re-checked with a hostile file: `{}` and `total:'1e999'` history entries are dropped; theme `theme-dark x` falls back to dark; the bad typed roll and the SVG picture are dropped. | Holds |
| Repudiation | Nothing is shared between people and there is no server log. | Nothing to fix |
| Info leak | **Analytics opt-out can be undone by a backup.** `saveLocalStats` writes `telemetryEnabled` from the stats object (analytics.ts:66). Someone who switched analytics off imports a file whose `usageStats.telemetryEnabled` is `true` (and that has no top-level `telemetryEnabled`). On the next open, `recordSessionStart` saves `telemetryEnabled=true`, and the open after that sends to GA again. The switch shows On, but nobody turned it on. | **Fix 1** (low; needs a hand-made or mismatched file). Reproduced: `telemetryEnabled` went `false` → `true` |
| Info leak | The share hash never reaches GA (`page_location` is split at `#`, and the hash is cleared on mount). The title is fixed. Save names aren't sent. `visitorId` stays on the device. | Holds |
| Denial of service | **A share-link "zip bomb".** lz-string packs repeats very tightly: a 19 KB link holds 15 MB of JSON (`[{},{},…]`), and a 2 MB URL can hold far more. Decompressing takes about 30 ms, but `JSON.parse` takes 1.4 s per 15 MB, and it runs twice (App.tsx:127 and :277). Measured load: 2.6 s against 0.9 s normally. Bigger links freeze or crash the tab. | **Fix 2** (low) |
| Denial of service | Storage full: the "Storage is full, so your last change wasn't saved" bar with Export backup appears, and the app keeps rolling. Analytics' own writes fail silently, which is fine. | Tested: works |
| Denial of service | A 1 MB Target Highlight from a backup: rolls still take about 250 ms and Customize opens in about 0.6 s. A 100 KB saved-game name or 3,000 games from a backup render, just slowly. Only hurts the person who imports the file. | Low; fix 3 caps the target box |
| Elevated access | No `eval`, `new Function` or `innerHTML` of outside data. The only `dangerouslySetInnerHTML` is our own landing article, copied from the page's DOM (App.tsx:1030, landing.ts:49). A `__proto__` key in saved games only changes the prototype of that one local object. There is still no CSP. | Fine. CSP: see below |

## Fixes (clearly right, for the lead to build)

**1. Check usage stats on load; the opt-out key is the only switch.**
`src/utils/analytics.ts:51-54`. Replace

```ts
    if (raw) {
      const parsed = JSON.parse(raw);
      return { ...getDefaultStats(), ...parsed };
    }
```

with

```ts
    if (raw) {
      const parsed = JSON.parse(raw);
      const base = getDefaultStats();
      // Stats can come from a hand-edited backup: keep only well-formed values
      const stats = { ...base, ...(parsed && typeof parsed === 'object' && !Array.isArray(parsed) ? parsed : {}) } as LocalAnalyticsStats;
      const nums = ['totalSessions', 'totalRolls', 'totalDiceRolled', 'totalSumRolled', 'highestRoll',
        'customDiceAddedCount', 'backupsExportedCount', 'backupsImportedCount', 'shareLinksGeneratedCount'] as const;
      for (const k of nums) if (typeof stats[k] !== 'number' || !Number.isFinite(stats[k])) stats[k] = base[k];
      const counts = stats.presetsLoadedCount;
      if (!counts || typeof counts !== 'object' || Array.isArray(counts)) stats.presetsLoadedCount = {};
      for (const k of ['visitorId', 'firstSessionTime', 'lastSessionTime', 'favoriteTheme'] as const) {
        if (typeof stats[k] !== 'string') stats[k] = base[k];
      }
      // The analytics switch alone decides; a backup's stats can't turn it back on
      stats.telemetryEnabled = base.telemetryEnabled;
      return stats;
    }
```

`setTelemetryEnabled` still works: it sets the flag after this read and saves both keys.

Test: put `{"telemetryEnabled":true,"presetsLoadedCount":null}` in `diceAnalyticsStats` and `"false"` in `telemetryEnabled`. Then `trackEvent('preset_loaded', {presetName:'Catan'})` must not throw, and `telemetryEnabled` must still be `"false"`.

**2. Cap a share link's JSON before parsing.**
`src/utils/setName.ts:61-62`. Add `const MAX_SHARE_JSON = 1_000_000;` near the top of the file. The largest real set is about 540,000 characters: 50 dice × 100 faces of 60 emoji characters plus picture, colour and value tags. Then replace

```ts
    const json = LZString.decompressFromEncodedURIComponent(data);
    return { dice: json ? sanitizeDiceList(JSON.parse(json)) : [], name };
```

with

```ts
    const json = LZString.decompressFromEncodedURIComponent(data);
    // A tiny link can unpack to many megabytes; anything past the largest real set is refused
    if (!json || json.length > MAX_SHARE_JSON) return { dice: [], name };
    return { dice: sanitizeDiceList(JSON.parse(json)), name };
```

The link then gets the existing "That share link couldn't be read" toast. Test: a link made from `'[' + '{},'.repeat(5e6) + '{}]'` returns `dice: []`.

**3. Cap Target Highlight from a backup.**
`src/utils/backup.ts:80`. Change `keep(SAVED.targetHighlight, data.targetHighlight)` to `keep(SAVED.targetHighlight, data.targetHighlight.slice(0, 200))`.

**Optional (spoofing, low):** in `readShareLink`, drop the name when it matches a built-in game's name but the dice don't match that game:
`const fake = name && dicePresets.some(p => p.name.toLowerCase() === name.toLowerCase() && diceSignature(p.dice) !== diceSignature(dice));` then return `name: fake ? null : name`. It's a product call: someone's own saved "Catan" variant would lose its name in the link.

Fixes 1, 2 and 3 are built in this pull request (src/test/review20261106.test.ts). The optional spoofing fix is left as a product call.

## Needs Daren

- **Deploy workflow hardening.** `.github/` is held for him. Today `npm ci` and the tests run with `pages: write` and `id-token: write`. Moving the build into its own job with `contents: read`, keeping only `deploy-pages` in a job with Pages rights, and pinning the actions to commit SHAs would mean a bad dev package can't deploy the site. Low urgency, because no outside code runs in this workflow.
- **CSP (carried over from 2026-10-30).** Still none. There's no XSS sink today, so it's hardening only. If it's done, it must allow the inline GA snippet and the service-worker registration (by hash, or by moving them to files), the font link's `onload`, googletagmanager and google-analytics, and `fonts.googleapis.com` / `fonts.gstatic.com`. Pull request 75 (dice-box, not in master) would also need `worker-src blob: data:`. A mistake breaks the public site, so it stays an idea for the Desk.
